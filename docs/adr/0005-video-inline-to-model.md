# Videos other than YouTube are downloaded and sent to the model inline, not by URL

OpenRouter forwards a video URL to the model only for Google AI Studio, and AI Studio accepts only YouTube links that way (OpenRouter docs, verified 2026-09-26). The video files behind an Instagram Reel, an X post or an Upload are plain mp4 URLs on a CDN or in Supabase Storage, so passing them by URL fails. Such a video is therefore downloaded by the reader and sent as a base64 `data:` URL in the `video_url` content part, which every Gemini provider accepts. The provider is still pinned to Google AI Studio whenever a video is present. Consequence: the request carries the whole file, and Gemini's inline limit is about 20 MB per request, so a video above 15 MB makes the Item Failed with a clear error. This is well below the 100 MB Upload limit from ADR 0004; larger videos need a different route (Gemini Files API is not exposed through OpenRouter), to be decided when Uploads land. Considered: sending only the thumbnail (loses what was said and shown, which is the point of analysing Reels), and calling the Gemini API directly for video (a second model integration; rejected while one provider suffices).
